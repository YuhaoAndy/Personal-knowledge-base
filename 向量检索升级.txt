🧠 一、核心思路（先建立框架）

RAG可以拆成三层：

1. 数据层（Data）
2. 检索层（Retrieval）
3. 生成层（Generation）

👉 所有优化，本质都在这三层里做文章

🚀 二、最重要：检索层优化（80%效果提升都在这里）
1️⃣ Chunk 优化（很多人第一坑）

问题：切得不好 → 检索不到关键内容

改进方法：
固定长度 → ❌（初级）
语义切分（按段落/标题）→ ✅
加 overlap（重叠窗口）→ ✅

👉 典型参数：

chunk size：300–800 tokens
overlap：50–150 tokens
2️⃣ 向量检索升级

基础版：

cosine similarity + top-k

进阶版👇：

✅ Hybrid Search（强烈推荐）

👉 向量检索 + 关键词检索（BM25）

优势：

语义 + 精确匹配兼顾
对专业词特别有效
3️⃣ Re-ranking（重排序，性价比极高🔥）

问题：

top-k 结果不一定最相关

解决：
👉 用一个小模型重新排序

流程：

query → 检索20条 → rerank → 选前5条

👉 效果提升非常明显，是面试加分项

4️⃣ Multi-query（多查询扩展）

问题：

用户问题表达不完整

解决：
👉 用 LLM 生成多个 query

例如：

用户问：怎么部署？
→ 生成：
- 部署步骤
- 安装流程
- setup guide
5️⃣ Query Rewrite（查询重写）

👉 把用户问题变成“更适合检索”的形式

例如：

原始：这个怎么用？
重写：FastAPI 路由使用方法
🧱 三、数据层优化（决定上限）
1️⃣ 数据清洗（很多人忽略）
去噪（广告、重复内容）
统一格式
去掉无意义文本

👉 脏数据 = 垃圾输出

2️⃣ Metadata（元数据）

给每个 chunk 加标签：

{
  "source": "API文档",
  "section": "认证",
  "date": "2024"
}

👉 可以做：

过滤（只查某类文档）
权限控制
3️⃣ Embedding 优化
换 embedding 模型（很关键）
不同语言用不同模型

👉 很多时候：

embedding模型 ≈ 检索效果天花板

4️⃣ 多模态（进阶）
PDF + 表格 + 图片
OCR + embedding
🤖 四、生成层优化（让回答更“像人话”）
1️⃣ Prompt 工程

核心点：

明确角色（你是专家）
强制引用来源
限制胡说（no hallucination）

例如：

只根据提供内容回答，如果没有答案就说不知道
2️⃣ 引用来源（非常重要）

👉 提高可信度

输出：

答案...
来源：
[1] 文档A
[2] 文档B
3️⃣ Structured Output（结构化输出）
JSON
表格
bullet points

👉 对“产品化”很重要

4️⃣ Answer Compression

👉 防止回答太长/太乱

总结
关键点提取
⚙️ 五、系统级优化（真正拉开差距）
1️⃣ 缓存（超实用）
相同问题直接返回
embedding缓存

👉 降成本 + 提速

2️⃣ Streaming（流式输出）

👉 用户体验提升很大

3️⃣ 权限控制（企业级）
不同用户看到不同数据
4️⃣ 评估体系（高级但重要）

你需要问：
👉 “我的 RAG 到底好不好？”

方法：

构建 QA 测试集
评估：
命中率
准确率
hallucination率
5️⃣ Agent 化（高阶玩法）

👉 不只是问答，而是“能行动”

例如：

查数据库
调 API
自动执行任务
